## 2024-05-04 - [Performance optimization pattern (SciPy Root-Finding)]
**Learning:** In heavily iterated numerical solver loops like `scipy.optimize.brentq` which evaluates scalars, substituting `numpy` mathematical functions (e.g., `np.sqrt`) with their standard Python `math` library equivalents (`math.sqrt`) inside the closure avoids significant NumPy scalar dispatch overhead.
**Action:** Always check variables inside mathematical closures (like `residual`) passed to numerical solvers; if they are guaranteed to be scalars, use `math` module functions instead of `numpy` to yield measurable speedups. Furthermore, algebraically expand equations to extract and hoist constant operations (like exponential terms) outside the closure.
